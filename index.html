The production core

Four connected surfaces. One StreamSuites system.

Choose the production surface that fits the room. Identity, permissions, rooms, destinations, and shared state remain coordinated underneath.

01
Closed access

StreamSuites Studio

Browser production workspace

Private Runtime-backed rooms with guests, layouts, branding, browser sources, and direct Cloudflare RealtimeKit media.

  • OFF AIR; recording and broadcast output are not shipped
  • Runtime-owned rooms, invitations, and permissions
  • Direct browser media—not a Python media path
Open Studio ↗
02
Windows Alpha

StreamSuites StudioApp

Native Windows production workspace

A native C#/.NET/WPF shell supervising a C++20 engine for local capture, preview, audio, recording, replay, and output foundations.

  • Native Windows app—not a WebView or wrapped site
  • Engine-owned local media and bounded IPC
  • Approved-tester download remains access-gated

StreamSuites Studio for OBS

OBS plugin and integration

Bring StreamSuites pairing, rooms, guest receiver foundations, and supported control surfaces into an existing OBS workflow.

  • OBS remains the media owner
  • Not an OBS fork or a Studio replacement
  • No StudioApp engine duplication

What StreamSuites is becoming

A complete production system—not a collection of disconnected utilities.

StreamSuites began with livestream automation and engagement foundations. Studio and StudioApp now sit at the center, with those systems becoming connected capabilities around the production workflow.

The result is one shared authority, multiple purpose-built production surfaces, and audience tools that remain interoperable without collapsing into one monolithic application.
